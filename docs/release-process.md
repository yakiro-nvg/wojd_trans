# Build and release

Clone with Git LFS and fetch its objects. Python 3.12 with `requirements.txt`, MSVC x64 Build Tools and the pinned repak packer are build dependencies; players need none of these.

`.github/workflows/build.yml` builds on master, release and refactor branches, pull requests and manual dispatch. The Windows job installs pinned dependencies, checks catalogs, executes independent inert installer/archive fixtures, compiles runtime/dump and both test profiles, tests every native dictionary rule in normal/far modes, runs the C8 setup checks and rejects test exports or external MSVC runtime dependencies in production DLLs. Capture and client coverage remain distinct from fixture coverage.

The package builder renders 296 FormatString files, cooks both V3 locres resources from exact route-specific bindings and validates the complete approved base inventory. Source keys, CRCs, target whitespace and newline forms are preserved. This includes validated stock and generated widget bindings that residual misses alone cannot reconstruct. Keep `resources/locres/manifest.json` and `config/base-payload.json` synchronized with reviewed changes; do not regenerate identity mappings from literal .data overlap.

`config/packages.json` declares VI_PATCH.zip (full runtime plus a Legacy choice) and VI_LEGACY.zip (DLL-free). The full package uses the freshly built runtime DLL (CAPTURE=0, SELFTEST=0, O2). Legacy contains no DLL/EXE/native catalog; `--variant legacy` builds without native binaries. Both keep the four-file HUD PAK at priority203 and main text/assets PAK at priority103. Legacy separately cooks observed DLL-free UE misses from `resources/legacy-locres`, reuses existing translations, and overlays the already built main-outline Han-Viet font into the UI faces. `config/legacy-payload.json` pins that complete layer. Collection-only local builds omit exactly the two translated locres routes and must not be published as a completed translation.

The builder binds the runtime DLL hash to production PE/profile checks and rejects dump/test profiles. Runtime editor metadata and raw captures are excluded. Every PAK is fully extracted and compared to staged bytes; every ZIP is fully reread. Both ZIP hashes and the source revision are authenticated before release staging. Vendor DbgHelp is copied/restored from the user's installation, never shipped. Installer fixtures cover both directions of profile switching, exact rollback, absence of active native components in Legacy and preservation of private settings. Legacy collection uses only readable PowerShell to archive a fresh game log; offline translation reuse never calls a provider.

Development builds upload reviewable artifacts without publishing. After a green source-branch run, fast-forward master/release to the reviewed revision. A push to release publishes only after its own successful build, using that run's artifacts, source revision, checksums and GitHub artifact attestation. Actions and repak are pinned. `local-unpublished` denotes a local build, not a hosted CI release.

Local checks mirror the workflow: install requirements; run unittest discovery; compile `work/catalog.bin` with `scripts/wojd.py compile-runtime`; run `native/build.cmd` for all four profiles, both `native/test_runtime.py` profiles, `native/test_c8_setup.py` and `native/check_artifacts.py`; finally run `scripts/build_package.py --repak <path>`.

The dump DLL remains a developer build target. The public player ZIP uses runtime; no dump ZIP is advertised in this release. Fresh capture runs must omit translated locres from both resource routes. Do not infer translation completeness, every UI layout or anti-cheat acceptance from passing build checks.
